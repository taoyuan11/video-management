# 帧库 · 本地视频管理

![帧库 · 叠帧标志](assets/branding/frame-library-256.png)

使用 Rust / iced 0.14、SQLite、GStreamer 的中文视频资料库，**仅支持 Windows 11 x64**。不支持 Windows 10、macOS 或 Linux。内容哈希去重、多标签管理、文件夹监听与内嵌播放，所有数据保存在本地。

界面使用 Windows 11 原生 Desktop Acrylic 磨砂微透明背景、圆角面板与轻柔投影，配合蓝色强调色、左侧导航、可收起的详情和批量命令。保留系统标题栏与原生文件选择器；界面文字使用内置思源黑体（Source Han Sans CN），无需安装字体，图标使用 Windows 11 Segoe Fluent Icons。字体来源及许可见 [assets/fonts/README.md](assets/fonts/README.md)。

左侧“设置”可调整并发线程数，**最小为 1，最大为启动时读取的 CPU 可用逻辑处理器数，默认 2 个**；读取失败时上限为 2，仅有 1 个可用逻辑处理器时默认使用 1。内容校验与封面生成共用上限，修改后对后续任务立即生效。正在执行的任务继续完成，播放和解码器自身的线程不计入此上限。设置自动保存在本地 SQLite 中，关闭再打开仍然有效；已保存的线程数超出当前范围时恢复默认值并提示。

外观支持 **浅色、深色、跟随系统**，默认浅色。跟随系统会响应 Windows 应用主题变化；主窗口、待处理窗口、标题栏和弹窗同步切换，透明材质不可用时使用对应主题的实色背景。

加载与扫描显示旋转指示，按钮悬停、列表切换、详情展开收起和弹窗入场带有轻量过渡。动画遵循 Windows“辅助功能 → 视觉效果 → 动画效果”设置，关闭后仍保留加载状态文字。

列表自动显示靠近片头的非纯色封面，跳过黑屏、白屏和彩色纯色片头。封面后台生成并按内容指纹缓存在 `data/cache/thumbnails`；相同内容的副本共用封面。快速取样或 10 秒处理预算内未找到合适画面时使用视频图标，仍可正常播放。首次选中视频后，详情直接加载视频首帧，保持暂停；鼠标移入画面显示文件名和播放控件，点击播放按钮后从视频开头播放。同一窗口正在播放时切换列表条目，新视频从头自动播放；暂停后切换仍保持暂停。

原生透明材质需要 Windows 11 build 22621 或更新版本，并受显卡能力和系统透明效果设置影响；材质不可用时自动使用实色背景。这是 Windows 11 内的能力回退。文字与视频保持清晰不透明。

- `Ctrl+O`：导入视频；`Ctrl+F`：聚焦当前窗口的搜索框。
- 列表右上角的信息按钮切换详情区；点击视频自动展开详情并加载待播。收起详情会停止并释放本窗口的视频，重新展开后加载为暂停状态。
- 主窗口和待处理窗口的详情播放器随侧窗宽度即时等比例缩放；极矮画面使用至少 128 px 高的容器并保持视频比例，空余处留黑边。竖屏视频超出可见高度时，可滚动查看完整画面和详情；Tab 聚焦播放器控件时会自动滚动到可见位置。
- 两处详情和全屏统一使用画面内控件：顶部为文件名，底部为进度、时间和操作栏。鼠标进入或移动时显示，静止 3 秒或移出画面后隐藏，播放、暂停和待播状态一致。拖动滑块、操作音量面板或键盘聚焦期间保持显示；隐藏不会改变画面尺寸。
- 播放器实际宽度小于 400 px 或高度小于 240 px 时自动使用 MINI 控件，按钮、文字、进度条、间距和竖直音量浮层同步缩小，减少画面遮挡；宽高均达到阈值后恢复常规尺寸。切换即时生效，保留播放进度、音量、焦点和自动隐藏规则，无需手动设置。
- 悬浮音量按钮向上展开竖直滑块和百分比，向上增大音量、向下减小，点击按钮切换静音。Tab／Shift+Tab 切换播放器控件，Enter／空格执行按钮，聚焦进度条时方向键调整 5 秒，聚焦音量滑块时调整 5%。
- 表头复选框选中／取消本页视频；多选用于添加或移除标签、导入资料库，不支持批量移除或删除视频。
- 主列表和待处理列表使用单行分页：显示总数、数字页码、每页 20／40／60 条和跳页输入；点击省略号可前后跳过 5 页，页码较少的紧凑布局跳过 3 页。窄布局显示“当前页／总页数”，输入页码后按 Enter 跳转；更改每页条数时保留原页首条视频所在位置。
- 列表顶部固定显示选择命令栏，选中或取消选择不会挤压列表；未选择视频时禁用相关操作。资料库保留“添加标签”“移除标签”，待处理窗口保留“选择标签”和“导入资料库”。右键点击某个视频唤出“从资料库移除”（待处理列表为“忽略此视频”）和“直接删除”菜单，仅针对该视频，不改变勾选、详情或当前播放，也不加载视频。列表行聚焦后可用菜单键或 Shift+F10 唤出菜单，菜单支持方向键、Tab、Enter／空格和 Escape。
- 搜索无结果、空标签、没有重复副本与文件均可访问时，显示对应的状态说明。

通用视觉与 UI 规范见 [design.md](design.md)，涵盖布局、颜色、字体、控件状态、动效和可访问性；产品功能与操作行为以本文和现有代码为准。

应用标志“叠帧”统一用于侧栏、标题栏、任务栏与可执行文件，所有图标嵌入 EXE，无需外置文件。矢量原稿、多尺寸 ICO 与导出说明见 [assets/branding/README.md](assets/branding/README.md)。

## 使用便携版

解压 `FrameLibrary-<版本>-windows-x64.zip` 到可写目录，运行 `video-management.exe`。请保留同目录的更新器、`release.json`、DLL、`lib`、`libexec`、`share` 等文件。无需安装 GStreamer 或修改系统 PATH。

1. **导入视频**：选择一个或多个视频；**添加文件夹**：递归扫描并监控该文件夹。
2. 新视频进入独立的 **待处理视频** 窗口。主窗口工作区右上角的同名按钮显示待处理总数，可打开或聚焦此窗口；资料库、标签管理和设置页均可访问。勾选视频后，点击“选择标签”可多选标签，再“导入资料库”；也可以先打开“标签管理”创建标签。不选标签时保留已有标签，新视频保持无标签。
3. 左侧可切换全部视频、无标签、重复副本、缺失文件。主视频列表顶部搜索框旁的“我的标签”支持多选“包含”和“排除”：只显示同时包含所有指定标签、且不含任一排除标签的视频，并与搜索和当前分类共同筛选。同一标签的包含与排除互斥，切换时自动取消相反条件；下拉菜单提供清除筛选和“标签管理”入口。选中视频后，通过“添加标签”“移除标签”批量勾选要修改的标签，其他标签保持不变。
4. 点击条目后，详情直接显示已加载的视频，无需先点击封面或独立的“播放”按钮。鼠标移入画面后点击播放按钮开始观看，可暂停、拖动进度、调节音量、静音、全屏；同一窗口播放中切换条目会从头自动播放新视频，暂停或停止后切换则保持暂停待播。Escape 退出全屏；普通模式下 Escape 停止播放并释放文件。
5. 点击条目查看完整 SHA-256 和所有路径，支持复制哈希、复制路径和选择具体副本播放。

每个视频可以有零个或多个标签，标签操作不会移动或重命名视频文件。标签按创建时间从早到晚排列，新建标签追加到末尾，重命名不改变顺序。相同 SHA-256 的文件合并成一个条目并共享全部标签，详情中保留所有文件位置。哈希比较的是完整文件字节；画面相似或重新编码的视频不视为相同内容。

左侧 **标签管理** 页面集中提供新建、重命名和删除标签，显示每个标签对应的资料库视频数量；筛选下拉也可打开此页。删除前会显示标签名称并要求确认。“返回视频列表”保留原来的搜索、筛选、分页与视频选择，待处理窗口的导入草稿也会保留。管理页支持 Tab／Shift+Tab、上下方向键切换操作，Enter 或空格执行。

标签筛选下拉支持连续勾选，点击外部或 Escape 收起并保留筛选；“清除筛选”同时清除包含和排除条件，恢复当前分类和搜索结果。下拉与标签选择弹窗均支持 Tab／Shift+Tab、上下方向键切换焦点，空格或 Enter 勾选／执行；标签选择弹窗中 Escape 取消草稿。列表显示前两个标签及其余数量，详情显示完整标签；下拉和弹窗中的长名称按字符换行。删除标签只移除对应关联及该标签的筛选条件，不影响其他标签和原文件。

## 删除、忽略与文件变化

- 在视频列表中右键点击单个视频执行操作，勾选其他视频不会扩大移除或删除范围。**从资料库移除**仅隐藏该视频的管理记录，原文件保留。**忽略此视频**用于待处理文件。两者都保存忽略标记，相同路径的内容未变化时不重复提醒；显式导入或内容变化后可重新处理。
- **直接删除**会永久删除文件，不经过回收站，**删除后无法恢复**。确认框显示该视频副本的完整路径，默认只选一个可访问副本，未选中的文件保留；可勾选同一视频的其他副本。确认前取消不会改变文件。执行前重新核对视频归属与哈希；文件变化或被占用时保留文件和记录并提示。删除正在播放的副本时先停止并等待文件释放。
- 确认删除后，两个窗口的工作区立即显示“删除中”状态卡，提示等待释放、等待扫描、校验及删除阶段和当前完整路径；多个副本显示真实处理数量。完成后明确显示“删除成功”“部分删除失败”或“删除失败”，异常原因默认展开，可查看每个文件的完整路径、原因与处理建议并复制结果。提示保留到手动关闭或下一次删除开始；执行期间禁用重复删除及移除命令，其他视频仍可浏览。
- 软件运行时监听监控目录，合并两秒内的事件，每 60 秒核对一次，启动时补扫。关闭待处理窗口不会丢失队列；关闭主窗口会完全退出，不驻留托盘。
- 正在复制、被写入或不可访问的文件稍后重试。子目录链接与 Windows junction 不递归进入，重叠监控目录不会重复记录。
- 已管理视频在监控范围内改名或移动，通过哈希关联并保留标签；新增副本需确认。外部删除或磁盘离线会保留缺失记录。
- 日常扫描通过大小和修改时间发现变化。**完整校验**重新读取全部文件，可发现内容已改变但大小、修改时间相同的情况。路径用于确认是否存在，SHA-256 用于确认内容身份。
- 视频列表提供“时长”列，点击表头切换升降序，未知时长始终排在最后。已有视频会在后台自动补齐时长，已读取的值在离线和重启后保留；**完整校验**可重试读取未知时长。
- 停止监控文件夹后不再发现其中未知视频；已导入文件仍会检查可访问性和变化。

默认识别：MP4、MKV、AVI、MOV、WMV、FLV、WebM、M4V、MPG、MPEG、TS、MTS、M2TS、3GP。实际播放取决于文件内的编码及运行库支持；损坏或不支持的文件仍可分类和管理。

## 监控文件夹迁移

在 **监控文件夹** 中点击某个文件夹旁的 **迁移**，选择目标父目录，核对完整路径后点击 **开始迁移**。例如将 `D:\视频\旅行` 迁移到 `E:\归档`，最终位置为 `E:\归档\旅行`。文件夹名称、内部结构、空目录、所有视频、字幕及其他文件一起保留；目标已存在同名文件或文件夹时停止，不合并、不覆盖。

支持同卷移动和跨磁盘复制后清理。迁移时暂停扫描、播放和两个窗口的业务操作，显示当前阶段、文件和复制字节进度。复制与校验阶段可以取消；更新资料库路径和清理原目录时需要等待完成。关闭主窗口会安全取消或完成收尾，并等待后台任务退出。

迁移后自动监控新位置，保留视频和文件记录、标签、时长、待处理及忽略状态；同一文件夹下单独添加过的监控子目录同步更新。文件夹外的副本保持原位。跨盘复制保留文件修改时间和 Windows 文件额外数据流，并在清理源文件前校验副本。

中断后，下次启动会在扫描前恢复：尚未提交的迁移回退，已提交的迁移继续清理原目录。被占用、被替换、发生变化或新增的内容会保留，显示具体路径；存在待恢复内容时扫描保持暂停，可从监控文件夹进入迁移结果并 **重试清理**。请根据提示先释放文件占用，或将需要保留的新增内容移到其他位置；不要直接删除 `.frame-migration-*` 临时目录或资料库中的迁移日志。

不能迁移磁盘／共享根目录、包含程序或当前资料库的文件夹，也不能移入自身子目录。首版不迁移含符号链接、junction 等重解析点的目录，也不迁移带额外数据流的目录本身；检查失败时会显示具体路径。

## 数据位置与备份

`data/library.sqlite3` 位于程序旁，保存视频、路径、标签、待处理、忽略记录、监控目录和设置。`data/cache` 保存运行缓存，`data/application.log` 记录扫描问题。复制软件目录可以带走资料库；视频本身始终留在原路径。

备份前关闭软件，再复制整个 `data` 文件夹。更新软件时保留 `data`。移动软件目录不会重写视频的绝对路径。调试和自动化测试可通过进程环境变量 `VIDEO_MANAGER_DATA_DIR` 使用隔离的数据目录。

首次打开旧资料库时，数据库自动升级至版本 4：原分组（包括空分组）转为同名标签，保留已管理、待处理和已忽略视频的关联，并支持保存视频时长和文件夹迁移恢复日志。升级后的资料库需要使用支持该数据库版本的软件打开。

## 软件更新

1. 点击左侧底部的 **软件更新**，选择一个本机磁盘或移动硬盘上的更新文件夹。更新源与视频监控文件夹相互独立，不支持 UNC 共享或网络映射盘。
2. 将完整 ZIP 发布包和配套的 `.update.json` 清单放在该文件夹的第一层。复制时先放 ZIP，最后放清单；不要修改文件名、版本或校验值。
3. 每次启动自动检查一次，也可以点击 **检查更新**。只提示版本号更高的正式版本；有多个版本时选择最高版本。
4. 发现新版后点击 **立即更新**，程序会复制、校验和解压发布包，保存资料库，退出并自动重启。点击 **稍后** 则本次运行不再自动提醒，下次启动仍会检查。手动检查可再次查看新版。

未配置更新文件夹时不检查。文件夹断开或无新版时不弹出阻塞提示；检查状态可在软件更新中查看。清除设置可停止启动检查。更新设置随当前资料库保存，不改变播放器音量设置。

更新器会保留 `data`、`VIDEO_MANAGER_DATA_DIR` 指向的数据和其他未受管理的文件，只替换清单中的程序与运行库，并清理旧清单中不再使用的文件。文件占用、无写权限、包不完整或哈希不符时停止更新；文件替换或启动进程失败时恢复旧程序。若恢复失败，保留 `.frame-update-*` 下的备份与 `rollback.jsonl`，并显示恢复位置；不要删除这些文件。断电等外部中断不会自动恢复，应保留任务目录并从完整便携包手动修复程序，保留资料库。

首次使用此功能需手动部署一个含更新器与 `release.json` 的版本。程序目录必须可写，不自动提升管理员权限。只使用自己信任的发布文件夹：SHA-256 用于检查完整性，不提供发布者签名认证。

## 开发与构建

需要 Windows 11 x64、Rust stable（支持 edition 2024，使用 `x86_64-pc-windows-msvc` 工具链）、MSVC C++ Build Tools 和 PowerShell 7。GStreamer 固定为 1.28.8，Rust 绑定为 0.25；本地 `iced_video_player 0.6` 补丁同步使用新版绑定及 GLib 0.22。SQLite 随 Rust 程序编译。

```powershell
./scripts/setup-deps.ps1
./scripts/run.ps1
```

依赖准备脚本从 GStreamer 官方站下载并验证 SHA-256，使用新版 EXE 安装包的官方 portable 模式，将运行库和开发文件解包至项目 `.deps/gstreamer/1.28.8/msvc_x86_64`，不进行全局安装或修改系统环境变量。不同 SDK 版本隔离存放，升级时重新运行脚本即可。构建用环境变量仅作用于当前 PowerShell 进程。

依赖准备完成后，`./scripts/build.ps1` 也支持在 Windows 11 自带的 Windows PowerShell 5.1 中执行，无需切换终端；首次下载依赖仍需 PowerShell 7。

### 在 RustRover 中运行

首次运行先执行 `./scripts/setup-deps.ps1`，然后在 RustRover 中打开项目根目录并等待 Cargo 加载完成。在右上角运行配置中选择项目自带的 **FrameLibrary**，点击运行或调试。如果新配置尚未显示，重新打开项目。

`.cargo/config.toml` 使用项目相对路径为 Cargo 提供 GStreamer SDK 和 `pkg-config`，因此 IDE 的构建与代码检查无需提前执行环境脚本。**FrameLibrary** 运行配置还会将播放组件的 `bin` 目录加入当前进程的 PATH，供 Windows 加载 DLL；不会修改系统环境变量。自动生成的 `Run video-management` 配置没有这项运行环境，请使用 **FrameLibrary**。`frame-library-updater` 是内部更新器，不是主程序入口。

终端启动仍使用 `./scripts/run.ps1`，或先执行 `. ./scripts/env.ps1` 再执行 `cargo run --locked`。只配置 `pkg-config` 能解决编译问题，但运行和完整测试仍需要播放 DLL 所在目录加入 PATH。

```powershell
# 纯数据库 / 扫描 / 服务测试，不需要播放依赖
cargo test --no-default-features

# 完整检查与便携包
. ./scripts/env.ps1
cargo fmt --check
cargo clippy --all-targets -- -D warnings
cargo test --locked
./scripts/build.ps1
```

版本统一取自 `Cargo.toml`。输出目录为 `dist/FrameLibrary-<版本>-windows-x64`，同时生成 ZIP、`.zip.sha256` 和 `.update.json`。每次执行构建脚本（包括 `-SkipBuild`）都会先清空项目的 `dist` 文件夹，再开始编译或打包，不保留旧版本、临时文件或 `.previous-*` 备份。`dist` 仅用于构建输出，其中手动放入的文件及运行便携版产生的 `data` 也会被删除；日常使用请将便携包解压到 `dist` 之外。若目录包含符号链接或 junction，或文件被占用导致清理失败，脚本会报错停止。

清理后，构建脚本构建不依赖 GUI/播放组件的更新器，校对两个 EXE 的 `--version`，从干净暂存目录包含播放 DLL、插件、许可证和包内文件清单，最后发布更新清单；包中不含用户 `data`。

发布包使用 `scripts/package-runtime.ps1` 中的本地播放插件清单，并通过 MSVC `dumpbin` 递归收集普通及延迟导入的 DLL；缺少插件或无法解析依赖时打包失败。保留常用容器、软件解码、Windows 硬件解码、音频输出和字幕组件，移除网络推流、采集、独立编码插件与 SDK 元数据。保留 GStreamer 许可证和字幕字体配置；不裁剪内置思源黑体。Rust 图像库只启用 PNG，保留 iced 的 GPU 和软件渲染回退。

`Cargo.toml` 的 release 配置使用 `opt-level = "s"`、完整 LTO、单代码生成单元及符号剥离，关闭调试信息和增量编译，进一步缩小主程序和更新器；代价是发布构建较慢。SHA-256 依赖单独保持 `opt-level = 3`，优先保证完整文件校验的吞吐量。保留 `panic = "unwind"`，使后台任务和封面生成的 `catch_unwind` 异常恢复继续有效；开发构建配置不变。

播放视频及字幕的输出队列各限制为两项；封面结果队列最多四项，同时最多两个封面任务，且仍受设置中的总并发上限约束。封面软件解码限制 libav 为单线程，减少高分辨率视频的参考帧内存。封面缓存最多 128 项，并以 16 MiB 为内存回收目标；当前页封面保留，两个窗口显示大量封面时可暂时超过此目标。这些限制不代表整个进程的内存上限，实际占用还受视频分辨率、解码器、显卡和资料库规模影响。

打包后可运行无窗口的隔离验证：

```powershell
./scripts/test-package.ps1 -Bundle ./dist/FrameLibrary-0.1.7-windows-x64
```

脚本生成临时视频样本，只从发布包加载运行库、插件和独立注册表，验证播放、暂停、跳转、音量、封面提取及文件释放；不会打开或操作桌面界面。升级 GStreamer 或调整插件清单后应重新执行。

发布新版本时先修改 Cargo 版本并运行构建，将生成的 ZIP 与对应 `.update.json` 放入用户配置的更新文件夹即可。不要只放 EXE 或只改 ZIP 文件名。发布清单包含 `product`、`version`、`platform`、`archive`、`size`、`sha256`；ZIP 内 `release.json` 包含产品、版本、平台和每个受管理文件的相对路径、大小、SHA-256。

## 代码结构

- `database`：SQLite 迁移、内容与文件位置、标签、忽略记录和事务。
- `scanner`：递归枚举、完整 SHA-256、最多两个哈希工作线程、取消和写入保护。
- `service`：数据库专用线程、文件监听、周期扫描、消息和有序退出。
- `update`：本机更新源检查、版本比较、安全解压、文件替换、备份回滚与更新锁。
- `frame-library-updater`：独立更新进程，等待主程序退出后更新并重启。
- `ui`：窗口状态、消息处理、分页列表选择与播放控制。
- `media`：播放与封面取帧共用的 Windows 文件地址转换，保留 UNC 网络共享和扩展长度路径。
- `ui/fluent`：Windows 风格的颜色、间距使用、图标与控件样式。
- `ui/views`：导航、资料库、详情、待处理窗口与对话框视图。
- `ui/backdrop`：Windows 11 原生 Acrylic、系统圆角与透明度能力回退。
- `vendor/iced_wgpu`、`vendor/iced_winit`：保留来源和 MIT 许可证的最小补丁，启用 DirectComposition、预乘 alpha 和正确的窗口合成标志。

测试均使用临时目录或项目内 `.qa` 样本，不扫描个人视频。永久删除测试只操作专门生成的临时测试文件，同时验证未选副本保留、跨视频请求被拒绝和文件占用保护。

```powershell
cargo test --no-default-features --test library
# 传入本地测试视频以检查播放控制和资源释放
. ./scripts/env.ps1
cargo run --release --example player_smoke -- 'C:/path/to/test-video.mp4'
```
